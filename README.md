# PuzzleHub

Мини-приложение с играми-головоломками. Тёмная «Auralis»-тема (ink + gold),
мультиязычность (`/ru`, `/en`), облачные сохранения с продолжением игры на другом устройстве.

> 🤖 **Работаете с ИИ-агентом?** Инструкции для агентов — в [AGENTS.md](./AGENTS.md)
> (архитектура, чек-лист добавления игры, дизайн-токены, известные грабли).
> `CLAUDE.md` подключает его автоматически для Claude Code; Cursor/Copilot/Codex
> читают `AGENTS.md` сами.

## Стек

- **React 19 + Next.js 16** (App Router, Turbopack)
- **TypeScript**, строгие типы везде
- **TanStack Query** — серверное состояние (сессия, сохранения)
- **Zustand** — состояние игр (доска, ходы, таймер)
- **TailwindCSS 4 + shadcn/ui** — UI
- **Framer Motion** — анимации (layout-анимации костяшек, staggered reveal, win-оверлей)
- **React Hook Form + Zod** — формы входа/регистрации и валидация API
- **Prisma 7 + SQLite** — база сохранений (легко мигрировать на Postgres)

## Запуск

```bash
npm install --legacy-peer-deps
npx prisma db push        # создаёт prisma/dev.db
npm run dev               # http://localhost:3000
```

Через Docker:

```bash
docker compose up --build
```

> **Важно про Docker + зависимости.** `node_modules` живёт в именованном
> volume, который Docker наполняет из образа только при первом создании.
> Контейнер теперь сам выполняет `npm install` на старте и доустанавливает
> новые пакеты, но если увидите `Module not found` после обновления
> `package.json` — пересоздайте volume: `docker compose down -v && docker compose up --build`.

Продакшен: `npm run build && npm start`.

### E2E (@playwright/test, `tests-e2e/`)

Собственный прод-сервер на порту 3199 с **изолированной БД** (`.e2e/e2e.db`,
пересоздаётся каждым прогоном в `global-setup.ts`); мобильный viewport 390×844.

- `landing.spec.ts` — редиректы по Accept-Language, fallback на `/en`,
  переключатель локали + cookie-приоритет, рендер всех секций, демо-игры
  (и что они **не** создают облачных сейвов), хаб со всеми играми;
- `games.spec.ts` — пятнашки: ход → автосейв (ждём реальный PUT) → перезагрузка →
  «Продолжить?» → прогресс на месте; смена размера поля; судоку: ввод цифр,
  счёт ошибок, заметки; 2048: стрелки двигают плитки, **позиции реально
  меняются** (база анимаций); мемори: найденная пара остаётся открытой;
- `sync.spec.ts` — регистрация через диалог (гость апгрейдится), ошибки входа,
  клиентская валидация; device-link целиком: QR + таймер → второй контекст
  переходит по ссылке → профиль и сейвы переехали → третий контекст получает
  «ссылка истекла»; живая синхронизация: чужой PUT → диалог «Обновлено на
  другом устройстве» → «Загрузить свежую версию» подменяет стейт.

### Coverage

`npm run test:coverage` → консольная таблица + HTML-отчёт в `coverage/index.html`.

Ключевые цифры ядра (unit-слой): движки игр **95–100%**, `session`/`telegram`/
`schemas` **~100%**, API-роуты **86–100%**, хуки **91%+**, proxy **100%**.
React-компоненты в этом отчёте показывают 0% — они сознательно покрываются
e2e-набором (vitest их не исполняет), поэтому «слепые зоны» смотрите так:
файл с 0% и без e2e-сценария = настоящая дыра; сгенерированный Prisma-клиент
и shadcn/ui исключены из отчёта.

Переменные окружения (опционально):

- `DATABASE_URL` — путь к SQLite (`file:/abs/path/dev.db`), по умолчанию `prisma/dev.db`
- `SESSION_SECRET` — секрет подписи cookie-сессии (обязательно поменять в проде)
- `TELEGRAM_BOT_TOKEN` — токен бота из BotFather; включает авторизацию через
  Telegram Mini Apps `initData` (без него эндпоинт отвечает 503, остальное работает)

## Мультиязычность

- URL-локали: `/ru/...` и `/en/...` — каждая версия индексируется отдельно,
  `alternates.languages` прописаны в метаданных.
- `src/proxy.ts` (Next 16 proxy/middleware) редиректит `/` → `/{locale}`:
  сначала смотрит cookie `ph_locale` (выбор пользователя), затем `Accept-Language`.
- Словари: `src/i18n/dictionaries/{en,ru}.ts`. Тип `Dictionary` выводится из `en.ts`,
  поэтому пропущенный перевод — ошибка компиляции.
- **Добавить язык**: добавить код в `locales` (`src/i18n/config.ts`),
  создать `src/i18n/dictionaries/xx.ts`, зарегистрировать в `get-dictionary.ts`. Всё.

## Хаб `/games` и Telegram Mini Apps

`/{locale}/games` — компактный список всех игр (одна колонка, крупные строки,
кольца прогресса), задуман как стартовая страница Telegram Mini App.
SDK `telegram-web-app.js` подключает сам `TelegramInit` (client component,
`next/script` со стратегией `afterInteractive` + `onReady`), поэтому
Telegram-интеграция работает на всех страницах:

- `TelegramInit` вызывает `ready()`/`expand()`, красит шапку/фон, отключает
  vertical swipes (конфликт со свайпами 2048);
- **авторизация**: `initData` отправляется на `POST /api/auth/telegram`,
  сервер проверяет HMAC-подпись токеном бота (+ свежесть `auth_date` ≤ 24 ч);
  гостевой прогресс мержится в Telegram-профиль, на втором устройстве
  тот же Telegram-аккаунт получает те же сохранения без email;
- **язык**: при первом открытии берётся `initDataUnsafe.user.language_code`
  (ru/en) и происходит редирект на нужную локаль — но только если пользователь
  ещё не выбирал язык вручную (cookie `ph_locale` имеет приоритет);
- **haptic feedback** (`src/lib/telegram-client.ts`): Telegram `HapticFeedback`
  внутри мини-аппа, `navigator.vibrate` как fallback в мобильных браузерах.
  Лёгкий тик — ход/переворот, impact — слияние/пара, success/error — итог партии.

**Поддержка web.telegram.org**: веб-версия Telegram открывает мини-апп в
кросс-сайтовом iframe, где браузер может блокировать сторонние cookie
целиком. Поэтому внутри Telegram каждый API-запрос несёт заголовок
`Authorization: tma <initData>` (обёртка `apiFetch` в `src/lib/api.ts`),
а сервер проверяет HMAC-подпись на каждый запрос и резолвит игрока по
`telegramId` без cookie (`resolveTmaPlayer` в `src/lib/session.ts`;
cookie, если браузер её принял, имеет приоритет). Дополнительно: в проде
cookie ставится с `SameSite=None; Secure`, CSRF-защиту даёт проверка Origin
в `src/proxy.ts` (с учётом `X-Forwarded-Host` за nginx), а встраивание в
iframe разрешено только Telegram через CSP `frame-ancestors`
(`next.config.ts`).

В BotFather укажите URL мини-аппа: `https://your-domain/ru/games` (или `/en/games`)
и задайте `TELEGRAM_BOT_TOKEN` на сервере.

## Демо в hero

Правая часть первого экрана — интерактивная демо-панель со всеми четырьмя
играми (переключатель: Пятнашки 3×3, мини-судоку 4×4, 2048, Мемори 4×3).
Без сохранений и бэкенда; стартовые позиции детерминированы (SSR-гидрация
без рассинхрона), случайность включается после первого действия.
В 2048 работают стрелки клавиатуры (скролл страницы подавлен), свайпы
пальцем и перетаскивание мышью (Pointer Events).

## Сохранения и кросс-девайс

1. При первом обращении к API создаётся **гостевой профиль** (httpOnly cookie, HMAC-подпись).
2. Каждый **ход** попадает в Zustand-стор → хук `useAutosave` дебаунсит и шлёт `PUT /api/saves/:game`
   (тики таймера не триггерят сохранение; макс. 1 запрос/сек, flush через `keepalive` при уходе со страницы).
   Индикатор «Сохранение…» показывается только если запрос длится дольше 600 мс,
   а «Сохранено» держится между сейвами — ничего не моргает.
3. **Живая синхронизация** (`useRemoteWatch`): открытая игра опрашивает сейв
   каждые 15 с + при возврате фокуса на вкладку. `useAutosave` запоминает
   `updatedAt` последнего собственного сохранения (`syncedAt`); если серверный
   `updatedAt` новее — значит, писало другое устройство, и показывается диалог
   «Обновлено на другом устройстве»: **«Загрузить свежую версию»** (стейт
   подменяется облачным) или **«Оставить мою»** (локальная версия немедленно
   пушится и становится главной). Собственные сохранения ложных срабатываний
   не дают; до первой синхронизации клиент молчит.
4. На другом устройстве: вход по email → cookie указывает на тот же профиль →
   при открытии игры приходит сохранение и показывается диалог «Продолжить?».
5. Регистрация **апгрейдит текущего гостя** — накопленный прогресс не теряется.

### API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/session` | Текущий игрок (лениво создаёт гостя) + список сохранений |
| POST | `/api/auth/register` | Регистрация (привязывает гостевой прогресс) |
| POST | `/api/auth/login` | Вход |
| POST | `/api/auth/logout` | Выход |
| POST | `/api/auth/telegram` | Вход через Telegram Mini Apps `initData` |
| POST | `/api/link-device` | Выпустить одноразовую ссылку «открыть на другом устройстве» |
| POST | `/api/link-device/claim` | Активировать ссылку на втором устройстве |
| GET/PUT/DELETE | `/api/saves/:game` | Загрузка / автосейв / очистка сохранения |
| POST | `/api/results` | Запись результата завершённой игры |
| GET | `/api/health` | Health-check для мониторинга (версия, аптайм, доступность БД) |
| GET | `/api/admin/stats` | Статистика для дашборда (заголовок `X-Admin-Key`) |

Все входные данные валидируются Zod (`src/lib/schemas.ts`), пароли — scrypt.

## Метрики и статистика

Встроенная аналитика без внешних сервисов (`src/lib/analytics.ts`): таблица
`Event` + `Player.lastSeenAt` в той же SQLite. Никаких IP и трекеров;
«визит» — не чаще раза в 30 минут на игрока.

**Дашборд** `/{locale}/admin` (вход по `ADMIN_KEY`): игроки (всего, DAU/WAU/MAU,
новые, гости/аккаунты/Telegram), график активности за 14 дней, статистика по
каждой игре (партии, игроки, ср. время/ходы), события за 30 дней и лента
последних завершённых игр. Автообновление раз в минуту. Без `ADMIN_KEY`
страница и API отдают 404.

Отслеживаемые события: `visit`, `register`, `login`, `telegram_login`,
`device_linked`, `game_finished`.

## «Открыть на другом устройстве»

Кнопка (иконка монитор+телефон) есть в шапке лендинга, хаба и каждой игры:

1. `POST /api/link-device` создаёт одноразовый токен (**TTL 5 минут**, nanoid-32)
   и возвращает ссылку `/{locale}/link/{token}`; в диалоге — QR-код, таймер
   обратного отсчёта и кнопка копирования. Повторный выпуск ссылки
   **аннулирует предыдущую** (активна максимум одна).
2. На втором устройстве страница `/link/{token}` вызывает
   `POST /api/link-device/claim`. Claim **атомарный** (`updateMany where usedAt: null`) —
   гонка двух устройств невозможна, второй получит 410.
3. **Разрешение конфликтов сохранений**:
   - второе устройство — чистое → просто получает профиль;
   - второе устройство — гость со своим прогрессом → для каждой игры
     побеждает сохранение с более свежим `updatedAt`; уникальные игры гостя
     переносятся; результаты переносятся; гостевой профиль удаляется.
     Пользователю показывается, какие игры взяты из локального прогресса;
   - второе устройство залогинено (email/Telegram) → **ничего не мержится
     и не удаляется**, сессия просто переключается на профиль из ссылки.
4. Страница `/link/*` закрыта от индексации (`robots: noindex`),
   истёкшие токены чистятся при каждом выпуске новой ссылки.
